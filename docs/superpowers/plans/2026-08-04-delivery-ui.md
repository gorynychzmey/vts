## Задачи

### 1. `GET /api/delivery-adapters`

Отдаёт по каждому загруженному адаптеру: `name`, `config_schema`, `secret_keys`,
`connection_fields`, плюс список несовместимых с причиной (`incompatible_adapters()`
из vts-9y7 — оператор должен видеть, почему плагин не поднялся).

- Схема ответа в `vts/api/schemas.py`.
- Тесты: список пуст без плагинов; отдаёт поля живого адаптера; несовместимые видны
  с причиной; секреты (значения) не появляются нигде.

**Осторожно:** `config_schema()` — это данные от плагина. Отдаём как есть, но
эндпоинт не должен падать, если адаптер бросил из `config_schema()`/`connection_fields()` —
один плохой плагин не должен ронять весь список (тот же принцип, что в registry).

### 2. Генератор форм по JSON Schema (frontend)

Новая функция: из `config_schema` + `connection_fields` строит поля.

- `type: string` → `<input type="text">`; `enum` → `<select>`; `boolean` → чекбокс;
  `integer`/`number` → `<input type="number">`.
- `required` → `required` на поле; `description` → `title`/подсказка.
- Разделение: поля из `connection_fields` идут в форму УЧЁТКИ, остальные — в форму
  ТАРГЕТА. `secret_keys` рендерятся как `<input type="password">` с плейсхолдером
  «задано»/«не задано» (значения с сервера не приходят — только `{set: bool}`).

**Осторожно:** неизвестный/сложный тип (`object`, `array`, `oneOf`) — не пытаться
угадать: показать текстовое поле с JSON и пометить. Иначе форма молча потеряет данные.

### 3. Диалог «Доставка»

Один `<dialog>` с двумя секциями: учётки и таргеты.

- Учётка: список (имя, адаптер, «используется в N», `adapter_available`), форма
  создания/редактирования по схеме (поля подключения + секреты).
- Таргет: список (имя, адаптер, учётка, `adapter_available`), форма с выпадающим
  списком учёток (фильтр по адаптеру!) + поля-параметры по схеме.
- Удаление учётки в использовании — сервер отдаёт 409 с числом; показать это внятно.

**Осторожно (из памяти проекта):**
- `applyI18n` затирает `textContent` — `data-i18n` на кнопке с иконкой убьёт SVG;
  label класть во внутренний `<span>`.
- `app.js` без `defer` — новые DOM-блоки, к которым обращаемся через `getElementById`,
  должны идти ДО тега `<script>`.

### 4. Deliveries в карточке новой задачи

Переиспользовать `renderPromptMultiselect` (он не завязан на промпты по сути — но
проверить: строки строит `buildPromptRow`, который читает `prompt.source/id/name`).
Если завязан — обобщить, а не копировать.

- Выбор таргетов + вариант (`raw`/`redacted`/`summary`) на каждый.
- Отправка: `delivery: [{deliver_to: "<target uuid>", variant}]` — **по uuid**
  (vts-929), не по имени.
- Недоступный таргет (`adapter_available: false`) — показать, но не дать выбрать
  (сервер всё равно отвергнет с 422).

**Осторожно:** вариант на КАЖДЫЙ таргет, а не один общий — две коллекции на одном
Outline могут получать разное (ровно ради этого делался vts-929).

### 5. Deliveries в пресете

То же в `#presets-dialog`; хранится в `preset.options.delivery`.
`filter_delivery_refs` на бэке уже нормализует записи и уже переведён на id.

**Осторожно:** у пресетов есть механика «висячих» ссылок (`preset.dangling_prompts`,
`filterDanglingPrompts`) — удалённый таргет в пресете должен вести себя так же
внятно, а не молча исчезать.
