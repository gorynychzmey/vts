# Tags — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-user tags on recordings, set at task creation, on cards and via presets; filter tasks and the library by tags (all/any); a tag management dialog; MCP and delivery carry tags.

**Architecture:** `tags` + `recording_tags` tables, one normalisation helper, repo methods for set/add/remove/list-with-counts; HTTP + MCP surfaces on top; filters in the shared filter helpers; a reusable tag-field component in `app.js` used by the form, presets, cards and filters.

**Tech Stack:** Python 3 / FastAPI / SQLAlchemy async / Alembic / Postgres / vanilla JS / Playwright UI scenarios.

**Spec:** `docs/superpowers/specs/2026-11-22-tags-design.md`

## Review Focus

1. **Case/whitespace variants** ("Бизнес-клуб", " бизнес-клуб ", "БИЗНЕС  КЛУБ" vs "бизнес клуб"): one tag, first spelling kept; filters match the same way. Test in Task 1 and Task 3.
2. **Deleting a tag used by many recordings**: links gone everywhere, cards and filters stop showing it, presets drop the id. Test in Task 2 and Task 5.
3. **All vs any with an unknown name**: all → empty, any → ignores it; list and count agree. Test in Task 3.
4. **Another user's tag id** in rename/delete/preset: 404, never cross-user access. Test in Task 2.
5. **MCP add/remove** never wipes unrelated tags; adding an existing tag is a no-op. Test in Task 4.

### Task 1: data model, normalisation, repo

**Files:**
- Modify: `vts/db/models.py` (`Tag`, `RecordingTag`; remove `Recording.tags`)
- Create: `vts/services/tags.py`
- Create: `alembic/versions/0037_tags.py` (`down_revision = "0036_drop_task_content_columns"`; create tables; drop `recordings.tags`; downgrade recreates `recordings.tags` as JSON `'[]'` and drops the tables)
- Modify: `vts/db/repo.py` (new section "Tags (vts-qwcj)")
- Test: `tests/test_tags_repo.py`

**Interfaces:**
- `vts/services/tags.py`: `class TagNameError(ValueError)`; `normalize_tag_name(raw: str) -> str` (trim + collapse whitespace; raises `TagNameError` if empty or > 64); `tag_key(raw: str) -> str` (`normalize_tag_name(raw).casefold()`); `dedupe_names(names: Iterable[str]) -> list[str]` (normalised, first spelling per key, order kept).
- `Tag`: `id` uuid pk, `user_id` FK users CASCADE, `name` String(64), `name_key` String(64), `created_at`; `UniqueConstraint(user_id, name_key)`. `RecordingTag`: `recording_id` FK recordings CASCADE, `tag_id` FK tags CASCADE, composite pk; index on `tag_id`.
- Repo:
  - `list_tags(user_id) -> list[tuple[Tag, int]]` — every tag with its count of linked recordings (all, listed or not), ordered by `name_key`.
  - `create_tag(user_id, name) -> Tag` (raises `TagExists` — define in `vts/services/tags.py` — if the key exists).
  - `rename_tag(user_id, tag_id, name) -> Tag | None` (None = not this user's; `TagExists` if the new key belongs to another tag; same key with new spelling allowed).
  - `delete_tag(user_id, tag_id) -> int | None` (number of unlinked recordings; None = not found).
  - `resolve_tags(user_id, names, *, create: bool) -> list[Tag]` (by key; creates missing when `create`).
  - `set_recording_tags(recording, names) -> list[Tag]` (replace set; creates missing).
  - `change_recording_tags(recording, add, remove) -> list[Tag]` (add creates missing; remove by key, unknown ignored).
  - `tags_for_recordings(recording_ids) -> dict[uuid.UUID, list[Tag]]` (one query; each list sorted by `name_key`).

### Task 2: HTTP API for tags, cards' tags, tags at creation, presets

**Files:**
- Create: `vts/api/routers/tags.py` (registered like the other routers)
- Modify: `vts/api/schemas.py` (`TagOut{id,name}`, `TagWithCountOut{id,name,count}`, `TagNameIn{name}`, `TagNamesIn{names: list[str]}`; `RecordingOut.tags`, `TaskOut.tags`/`TaskCompactOut.tags`: `list[TagOut]`; `TaskCreateRequest.tags: list[str] = []`; `PresetOptions.tags: list[str] = []` (tag ids))
- Modify: `vts/api/routers/recordings.py` (`PUT /api/recordings/{id}/tags`; `_serialize` gets tags), `vts/api/routers/tasks.py` (`PUT /api/tasks/{id}/tags` adapter; create/upload paths pass `tags`; list/get serializers pass tags), `vts/api/routers/uploads.py` (multi-file init accepts `tags`), `vts/api/_helpers/serialization.py`, preset routes/service (read drops unknown ids; save keeps only this user's existing tag ids)
- Modify: `docs/API.md`
- Test: `tests/test_tags_api.py`

**Interfaces:**
- `GET /api/tags` → `list[TagWithCountOut]`; `POST /api/tags {name}` → 201 `TagOut` / 409 / 422; `PATCH /api/tags/{id} {name}` → `TagOut` / 404 / 409 / 422; `DELETE /api/tags/{id}` → `{"unlinked": n}` / 404.
- `PUT /api/recordings/{id}/tags {names}` → `list[TagOut]`; `PUT /api/tasks/{id}/tags {names}` → same via the task's recording (404 as the other task adapters).
- Card serializers load tags with `tags_for_recordings` once per page.
- `tags` on task creation is applied to the recording created with the task in the same transaction; invalid name → 422 before anything is created.
- Presets: `options.tags` = tag ids; on read, ids that are not this user's existing tags are omitted; system presets always `[]`.

### Task 3: tag filters for tasks and the library

**Files:**
- Modify: `vts/db/repo.py` (`_apply_task_filters`, `_apply_recording_filters`, list/count signatures), `vts/api/routers/tasks.py` (`list_tasks`, `count_tasks`), `vts/api/routers/recordings.py` (`list_recordings`), `docs/API.md`
- Test: `tests/test_tag_filters.py`

**Interfaces:**
- Both helpers take `tags: list[str] | None = None, tag_match: Literal["all","any"] = "all"`. Names are keyed with `tag_key`; invalid names → treated as unknown. `all`: every given key must be linked (unknown → empty result). `any`: at least one known key linked (unknown ignored; all unknown → empty). Task filter joins `recordings` on `source_task_id`.
- HTTP: repeatable `tag` + `tag_match` on `GET /api/tasks`, `GET /api/tasks/count`, `GET /api/recordings` (bad `tag_match` → 422).
