# План: учётка отдельно от таргета + валидация config_schema (vts-929)

**bd:** vts-929. Отделено: vts-j2kh (web UI), vts-2rxl (deliver_to по имени).
**Решение:** записано в vts-929, здесь не пересматривается.

## Подтверждённые решения Victor (2026-08-04)

- Ссылка таргет→учётка **по uuid**, не по имени: переименование не должно рвать сцепку.
  Обе сущности уже имеют UUID PK — ссылка это обычный FK, новых идентификаторов не нужно.
- Ссылка **обязательна** (единообразие важнее лишней сущности).
- **Валидация `config_schema` — включена** в эту задачу.
- **Web UI — вне** этой задачи (vts-j2kh); его сейчас не существует вовсе.
- Миграция: таргетов в проде нет, переносить нечего. Написать корректно, но без дедупликации.

## Что подтверждено чтением кода

- `DeliveryTarget` (`vts/db/models.py:219`): `adapter`, `config_json`, `secrets_enc`,
  UniqueConstraint `(user_id, name)`, UUID PK.
- Расшифровка секретов ровно в двух местах: `vts/delivery/consumer.py:51-55` (доставка) и
  `vts/services/delivery_submit.py:36-44` (сериализация для API/MCP).
- CRUD дублируется в REST (`vts/api/main.py`) и MCP (`vts/mcp/tools.py`) поверх общего `Repo`.
- **Валидации `config_schema` сегодня НЕТ нигде** — ни REST, ни MCP не проверяют config.
  `config_schema()` только отдаётся наружу. Пункт «валидировать мерж» = ввести валидацию впервые.
- Адаптер сегодня НЕ объявляет, какие поля относятся к подключению — это надо добавить.

## Задачи

### 1. Контракт: адаптер объявляет поля подключения

`vts/delivery/contract.py`: добавить в Protocol метод, возвращающий имена полей подключения
(например `connection_fields() -> list[str]`). «Параметры» = всё остальное, вычитанием.

- Ядро НЕ знает, что «учётка = url + token» — границу объявляет адаптер (обоснование в vts-929).
- Адаптер без подключения возвращает `[]` → учётка ему не нужна.
- **Это ДОБАВЛЕНИЕ → MINOR.** Bump `CONTRACT_VERSION` до `(1, 1)` по правилу из vts-9y7.
- **Осторожно:** метод обязателен в Protocol → адаптеры без него перестанут проходить
  `isinstance`. Чтобы не ломать сторонние плагины на `contract_version=(1,0)`, читать через
  `getattr(adapter, "connection_fields", None)` с дефолтом `[]`, а в Protocol объявить
  опциональным по факту. Проверить тестом на адаптере без метода.

### 2. Модель + миграция

- Новая `DeliveryCredential`: `id` (UUID PK), `user_id`, `name`, `adapter`, `config_json`,
  `secrets_enc`, timestamps. UniqueConstraint `(user_id, name)` — как у таргетов.
- `DeliveryTarget`: добавить `credential_id` (FK → `delivery_credentials.id`), убрать
  `secrets_enc`.
- Alembic `0022`: создать таблицу, добавить FK-колонку, перенести данные (пусто в проде),
  удалить `secrets_enc` у таргета.
- **Осторожно:** `ondelete` для `credential_id`. НЕ `SET NULL` — ссылка обязательна.
  `RESTRICT`, и удаление учётки, на которую ссылаются, отдаёт внятную 409, а не падает
  IntegrityError.

### 3. Мерж + валидация схемой

Одна функция в services (общая для REST/MCP/consumer): по таргету и его учётке отдаёт
плоские `config` и `secrets`.

- Порядок: учётка → таргет (поле таргета перекрывает поле учётки).
- Валидация `config_schema()` адаптера — по РЕЗУЛЬТАТУ мержа. У таргета в одиночку нет
  `base_url`, а он в `required` (`vts-outline/vts_outline/__init__.py:67`).
- **Осторожно:** адаптер может быть не загружен (`UnknownAdapter`) — тогда валидировать
  нечем. Не падать: пропускать валидацию, как уже делает `delivery_target_view`.
- **Осторожно:** нужна ли jsonschema как зависимость — проверить, есть ли уже в проекте.

### 4. CRUD учёток (REST + MCP)

Паритет с таргетами: `/api/delivery-credentials` (CRUD) + MCP-инструменты.
Секреты write-only, наружу только `{key: {set: bool}}` — переиспользовать логику
`delivery_target_view`.

- У учётки в выдаче — `used_by` (число таргетов), пригодится для vts-j2kh и для внятной
  ошибки при удалении.

### 5. Consumer + сериализация

- `consumer.py`: брать секреты из учётки, конфиг — из мержа.
- `delivery_target_view`: секреты теперь у учётки; отдавать `credential_id`.

### 6. vts-outline

Объявить `connection_fields() -> ["base_url", "api_token"]`, `contract_version` оставить
`(1, 0)` — адаптер не требует новой минорной фичи, он её лишь предоставляет.
**Проверить:** это надо обдумать при реализации — если ядро начнёт ТРЕБОВАТЬ метод,
версия должна вырасти; если читает через getattr с дефолтом — нет.
