# Redesign v2 — план внедрения

Ветка `feat/redesign-v2`. Источник: `docs/design-v2/` (прототип, `vts-theme.css`,
записка дизайнера). Принято 2026-08-17.

## Принципы

1. **Разметку не переименовываем.** 147 `id`, 214 `data-i18n*` и классы
   состояний (`hidden`, `active`, `disabled`) — контракт с `app.js`.
   Нужна другая структура — оборачиваем, сохраняя `id` на месте.
2. **Комментарии в `styles.css` сохраняем.** В файле ~40 блоков вида
   «почему так, а не иначе» (переполнение строки языка, порядок
   `.btn-text` после глобального `button`, anti-flicker для закрытого
   `<dialog>`). Это оплаченное отладкой знание; при переносе на токены
   меняются значения, не объяснения.
3. **Каждый этап проверяем в браузере** через `verifier-web` — реальный
   Chromium со стабами `/api/*`, обе темы.

## Этап 1 — токены и тёмная тема

- Перенести `:root` из `vts-theme.css` (84 токена) в `styles.css`,
  сохранив старые имена как есть; `--accent-2` оставить алиасом `var(--ok)`.
- Блоки тёмной темы: `:root[data-theme="dark"]` и
  `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`.
  `color-scheme` — обязательно, иначе нативные контролы останутся светлыми.
- Шрифты Manrope + IBM Plex Mono положить **локально** в
  `vts/static/fonts/`, не с Google Fonts: сервис самохостится, PWA должна
  работать офлайн, и внешний CDN сливает IP пользователей.
  Ссылку на шрифты версионировать через `?v=__VTS_VERSION__`, как это
  уже сделано для скриптов.
- `@keyframes vts-flash-light` содержит единственный хардкод-цвет
  (`#fdf1e7`) — завести токен.

**Проверка:** страница выглядит как раньше (значения ещё старые), тёмная
тема переключается атрибутом вручную.

## Этап 2 — переключатель темы (3 состояния)

Дизайнер сделал бинарный цикл. Нужен трёхпозиционный:
**система → светлая → тёмная → система**, умолчание — система.

- `localStorage` ключ `vts_theme` (префикс `vts_` уже используется для
  `vts_auth_user`, `vts_as_user`). Значения: `light`, `dark`, отсутствие
  ключа = система.
- **Анти-вспышка:** инлайновый скрипт в `<head>` ДО `styles.css`, который
  ставит `data-theme` из `localStorage`. Иначе при тёмной теме будет
  вспышка светлой на каждой загрузке. Скрипт обязан быть инлайновым —
  внешний файл грузится асинхронно и не успеет. Инлайновый скрипт в
  `index.html` уже есть (регистрация SW, строка ~602), но он в конце
  `<body>` — для темы нужен отдельный, в `<head>`.
- Кнопка `#theme-toggle-btn` в шапке: три иконки по состоянию,
  `aria-label` и `title` через `data-i18n-*`. Новые ключи:
  `theme.system`, `theme.light`, `theme.dark` в ru/en/de.
- `<meta name="theme-color">` с `media`-вариантами для светлой/тёмной;
  манифест: `theme_color: #c5532a`, `background_color: #efeae0`
  (сейчас там рассогласование — старый акцент и почти чёрный фон).
- Тема должна применяться и внутри `<dialog>` — они рендерятся в top layer.

**Проверка:** выбор переживает перезагрузку; вспышки нет; системная тема
подхватывается при отсутствии ключа; смена системной темы на лету
работает, пока выбор = система.

## Этап 3 — 136 хардкод-цветов на токены

Механическая, но объёмная часть. По секциям, не одним махом; после каждой
секции — визуальная сверка светлой темы со скриншотом «до». Цель: ноль
хардкод-цветов вне блоков токенов.

## Этап 4 — компоненты по секциям

Порядок: шапка → композер → список задач → диалоги.

### 4.1 Композер и мультизагрузка (`vts-???`)

Сейчас: `multiple` работает, submit читает `Array.from(fileInput.files)`,
но **разметки для показа выбранного нет вообще**. Пользователь не видит,
что выбрал; не может убрать один файл; повторный выбор ЗАМЕНЯЕТ набор.

Реализация:
- Источник правды — `File[]` в состоянии, не `fileInput.files`
  (`FileList` неизменяем). `fileInput.files` пересобирать через
  `DataTransfer` — приём уже используется в share-хендлере (`app.js` ~6191).
- Классы дизайна: `file-drop*`, `file-list`, `file-row*`, `file-foot*`.
- **Дедупликация:** по паре `name`+`size`, дубликат НЕ добавляем и
  **предупреждаем** (решение Victor, 2026-08-17).
- **Порядок:** перетаскивание строк. Порядок значим — N файлов
  склеиваются в `extract_audio`, поэтому номер показываем всегда.
  Drag должен иметь клавиатурную альтернативу (кнопки вверх/вниз или
  `aria-grabbed`), иначе фича недоступна с клавиатуры.
- Новые ключи i18n: сводка по файлам, «добавить ещё», «убрать файл»,
  предупреждение о дубликате, подсказка про порядок.

**Проверка:** выбрать несколько, удалить средний, поменять порядок,
добавить ещё — и убедиться, что улетает правильный набор в правильном
порядке.

## Риски

- **`app.js` не имеет `defer`.** Новые DOM-блоки, которые ищутся через
  `getElementById`, обязаны идти ДО `<script>`.
- **`data-i18n` затирает `textContent`.** На кнопке с иконкой ключ должен
  висеть на внутреннем `<span>`, иначе SVG уничтожается при переводе.
- **Контраст.** Цифры дизайнера (7.4:1, 4.6:1, 4.9:1) выглядят
  правдоподобно, но проверить самостоятельно.
- **PWA-кэш — риска НЕТ.** Проверено: `sw.js` не кэширует статику
  ("No asset caching; index is served no-store"), единственный кэш —
  `vts-share-inbox` для share-target. Бампать версию кэша не нужно;
  версионирование идёт через `?v=__VTS_VERSION__` на `<script>`.
